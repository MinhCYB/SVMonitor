# SVMonitor v0.1.2 tray UX plan

Autonomous implementation per request; no approval gate. No monitoring/SSH behavior changes, new GUI dependency, animation or extra polling.

## Constraints and decisions
StatusNotifierItem supports ARGB icon pixmaps and tooltip; DBusMenu supports themed icons, PNG icons, separators, nested menus and standard/checkmark items, not arbitrary cards, fonts, progress widgets or custom colors. Keep native host rendering. Plain ASCII menu labels, themed action/status icons with text fallback. Escape underscores in user-controlled labels (DBusMenu mnemonic syntax).

- Identity: small server-rack glyph, dual light/dark contour on transparent background, status badge uses distinct shape as well as color. Static cached pixmaps at 16/22/32/48 pixels; no animation. No red icon override for non-down attention.
- Top level: summary, urgent servers before healthy, at most eight direct servers; for larger fleets page groups of at most eight with stable ordering. Disabled servers under a separate submenu. No server may disappear from navigation. Secondary settings/import/history/autostart under a compact management submenu.
- Server submenu: short state heading and cause; SSH and Tailscale separate; fresh CPU/RAM/disk quick view, full metrics/system in a deeper Details submenu; old data explicitly marked stale for every non-available SSH state; resource alerts textual and decorated with standard warning icons. Primary actions Open SSH and Check now near the top. Recent events collapsed, not five unsolicited rows. Removal behind Manage.
- Tooltip: concise counts including retry/checking/disabled, up to five highest-priority server summaries and an overflow count. Escape markup, sanitize control text. Do not depend on tooltip support for essential state.
- Actions: callbacks queue commands, never wait for engine replies while tray locked. Immediate 'Check queued'/'Checking...' feedback; no repeated refresh while snapshot.probing. Failed launcher/autostart surfaced in menu feedback rather than stderr only. Reload current terminal settings on menu open as existing code.

## Work slices
1. Icon module and tests: independent procedural rasterization and cache; no new dependency.
2. Tray presentation/menu and regression behavior: use existing engine commands and launcher APIs, own tray.rs and DBus integration assertions.
3. Parent integration: version 0.1.2, docs, installed build, real D-Bus menu clicks, native captures in light/dark, many-server snapshots via isolated test engine (simulated states clearly labeled), benchmarks, local commits only.

## Verification
Tests first for hierarchy bounds/no omissions, urgency ordering, stale data, mnemonic escaping, tooltip overflow and refresh command behavior. Real menus via GNOME AppIndicator and GTK/libdbusmenu host; image captures are actual native widgets, not fabricated mockups. State simulation uses disposable config and fake read-only SSH, never disrupt real servers. Restore any desktop theme settings and leave original config unchanged. Full cargo tests/clippy/build; idle and disconnected benchmarks on final binary. No push.

## Review decisions and verification
Final review found timestamp-based global refresh could complete early and asynchronous mutation errors were dropped. Replaced timestamp heuristics with per-server monotonic completion counters (serde-defaulted for older snapshots), retained reply receivers and consumed them without blocking on menu open. Borrowed sorted server views rather than cloning metrics. Rendered toggle captures its displayed state. Added mixed-wave and 150-server recursive navigation regressions; full suite 112 passed, strict clippy clean. Actual 28-enabled/32-total fake fleet refresh completed every requested counter; a read-only config directory produced a visible save error.

Ruling: retain existing synchronous local menu-data reads and terminal resolver behavior; these predate this UX change and were not regressions. Cost: slow local files/preferences can delay opening the menu.
Deferred minor: GNOME AppIndicator may leave extra underscores in multi-name page range labels; GTK labels are correct and navigation is intact.
Deferred inherited limitation: enable/remove save errors are visible but their runtime changes are not rolled back. No production config failure was induced; error smoke used only the disposable fixture.
